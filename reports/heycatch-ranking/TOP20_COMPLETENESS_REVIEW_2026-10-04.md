# Top 20 source apps: completeness and feature opportunities

Reviewed October 4, 2026 against the 20 original source folders in [TOP20](/Volumes/external/projects/inspection-2026-09-05/organic-paid-growth/TOP20.md), as mapped by [COMPARISON_WITH_TOP20](COMPARISON_WITH_TOP20.md). This assesses each *source app*, not the merged platform that may contain some of its features.

**Implementation follow-up:** [October 4 status for all 20 apps](TOP20_IMPLEMENTATION_STATUS_2026-10-04.md) supersedes the initial-state descriptions below. The table below remains the priority baseline that the user approved.

## Verdict and method

**None is verified as a complete, production-ready app.** Five have substantial slices of their core workflow (homeservices, beautyhqio, grant workspace, petGrooming, independentRestaurant); those slices still have launch conditions. The other 15 range from partial governed backends to local calculation/draft prototypes. A passing build or unit test proves only the code path it exercises.

I read each app's current operations/status docs, inspected representative route/service code and frontend references to the primary workflow, ran available safe local tests, and checked buildability. I did not submit payments, messages, claims or regulatory filings, connect real providers, migrate operational databases, test mobile devices, or conduct user acceptance. Suggestions below are product priorities, not claims that the current app already performs them.

**Checks:** All 20 available local test suites/commands passed; BeautyHQ skipped 24 database/provider tests, and Content Repurposing skipped three integration tests. Production frontend/app builds now pass for 19 apps; `petGrooming` passed after removing an invalid Next route export. `AIConstructionBidAnalyzer` built after `npm ci` repaired its incomplete local `react-scripts` installation. `AIInvoiceProcessing` has a static client without a build script; `node --check` passed for its client and server entry points. No provider acceptance was established by these checks.

**October 4 implementation update:** Removed the invalid route export in `petGrooming`; its production build now passes. Added a CSV/JSON statement import and review screen to each of the four recovery apps. Each frontend build and existing backend suite passes. Their statement checksum uniqueness is now scoped to the selected capability, with repeat imports showing the saved reconciliation. This database migration still needs application in each deployment. The new screens label calculated positive differences as source-supported variances and state that a received credit is not verified. Provider settlement, contract rules, claims, credit receipts, and tenant isolation remain open. A governed case, evidence, and decision screen was also added to `AIReviewResponseManager`; its frontend build and 12 governance tests pass, while review-platform ingestion and publication remain unconfigured.

## Cross-app priorities

1. **Connect the actual UI to the governed workflow** before adding more feature pages. This is the largest gap in the legacy React apps at ranks 6–8 and 13–20. Keep generated/legacy routes visibly unavailable rather than advertising them as completed actions.
2. **Prove one real external outcome per app.** A provider receipt, customer approval, accepted packet, published artifact, or credited refund is stronger evidence than a dashboard status. For the four recovery apps, rename positive variances to *supported candidate recovery* until actual credit/payment evidence exists.
3. **Add AI only after the evidence path works.** The best AI additions extract, cite, explain and prioritize; deterministic rules and accountable people retain financial, safety, legal, accessibility and publishing decisions.
4. **Retest the scoped launch journey with real operators and provider sandboxes.** Local unit suites and builds do not cover registration, migrations, multi-tenant access, actual deliveries, hardware, mobile offline conflicts, or support/recovery procedures.

My near-term order remains one narrow pilot from homeservices, BeautyHQ or the grant workspace, based on buyer access. The updated code makes all three more credible than the September report suggested, but none is certified ready for an unsupervised public launch. Pet grooming now builds; the restaurant app has a narrower authenticated pickup offer worth testing after provider acceptance. The recovery apps should be sold only as manual, evidence-reviewed audits until domain rules, tenant isolation and verified credits are complete.
